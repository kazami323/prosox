# Миграция Prosox Data на Next.js — дизайн

Дата: 2026-09-22

## Контекст

Есть статический одностраничный прототип `prosox-data-v3_4.html` (1391 строка,
HTML+CSS+JS в одном файле) — лендинг сервиса выгрузки данных Prosox Data.
Сайт визуально готов (стиль «isometric soft-tech»: тёплый off-white лист,
матовое стекло, один циановый акцент) и функционален (табы, форма, скролл-меню,
reveal-анимации), но живёт как один файл без тулинга, без контроля версий,
без возможности удобно вносить будущие дизайн-правки покомпонентно.

Цель этой задачи — перенести существующий прототип 1:1 в проект на Next.js,
сохранив внешний вид и поведение, чтобы дальше было удобно вносить дизайн-
изменения по частям (компонент за компонентом), не трогая один гигантский файл.

## Нефункциональные цели

- Визуальный и функциональный паритет с прототипом — без регрессий.
- Разбивка на компоненты по секциям, чтобы будущие дизайн-итерации были
  локальными правками, а не поиском по одному файлу.
- Годный git-репозиторий: осмысленная история коммитов, `.gitignore`.

## Явно вне рамок (не делаем сейчас)

- Подключение формы заявки к реальному бэкенду (остаётся прототипом:
  та же клиентская валидация и honeypot, экран «готово» без отправки данных).
- Реализация EN/VI переключателя языка (кнопки остаются заглушками «скоро»,
  как в прототипе).
- Переход на Tailwind/CSS Modules — дизайн-токены (CSS custom properties)
  переносятся как есть в глобальный CSS.
- Любые визуальные изменения дизайна — это отдельная задача после миграции.

## Стек

- **Next.js, latest stable release, App Router, TypeScript.** (Resolved to 16.3.5 when Task 1 ran `create-next-app@latest` — see the implementation plan's ledger for the ruling. This spec was written when Next.js 15 was current; there is no technical requirement pinning the major version, so "latest stable" is the actual intent, not "15" specifically.)
- Глобальный CSS (`app/globals.css`) — текущий `:root` с токенами и все
  существующие классы переносятся без изменений содержимого.
- Шрифты Manrope и IBM Plex Mono — через `next/font/google` вместо
  `<link rel="stylesheet">` (тот же визуальный результат, меньше блокировок
  рендера и мельканий).
- Пакетный менеджер — npm (без внешних требований к деплою на этом этапе).

## Структура проекта

```
app/
  layout.tsx        — <html>/<body>, подключение шрифтов и globals.css
  page.tsx           — собирает секции в порядке текущей страницы
  globals.css         — перенесённые токены и стили
components/
  Nav.tsx             — client: бургер-меню, scroll-spy активного пункта, языковая заглушка
  MobileMenu.tsx       — часть Nav или отдельный подкомпонент (по месту)
  Hero.tsx
  sections/
    Komu.tsx
    Kak.tsx
    Vid.tsx
    Formaty.tsx        — client: переключение вкладок форматов
    Instrumenty.tsx
    Cobi.tsx
    Zakon.tsx
    Ceny.tsx
    Faq.tsx
    Materialy.tsx
    Zayavka.tsx        — client: форма, валидация, honeypot, экран «готово»
  Reveal.tsx            — client: переиспользуемая обёртка на IntersectionObserver
                          вместо текущего глобального скрипта прокрутки
  BackToTop.tsx         — client: кнопка «наверх»
  Footer.tsx            — если в прототипе есть подвал за пределами секций
public/
  prosox-mark.webp (или .png) — вынесенный из base64 логотип-знак
```

Разбивка компонентов повторяет текущие `id`-якоря секций
(`komu`, `kak`, `vid`, `formaty`, `instrumenty`, `cobi`, `zakon`, `ceny`,
`faq`, `materialy`, `zayavka`) — так проще сверять с прототипом и находить
нужный кусок для будущих правок.

Большинство секций — серверные компоненты (статичная разметка + текст).
Клиентскими (`"use client"`) становятся только те, что реально используют
интерактивность в браузере: `Nav`, `Formaty`, `Zayavka`, `Reveal`, `BackToTop`,
языковая заглушка (может быть частью `Nav`).

## Перенос поведения (текущий inline `<script>`)

| Поведение в прототипе | Реализация в Next.js |
|---|---|
| Мобильное бургер-меню (открыть/закрыть) | `useState` в `Nav.tsx` |
| Табы форматов (клик + стрелки, ARIA) | `useState` в `Formaty.tsx`, та же ARIA-разметка |
| Подстановка темы заявки из `data-req` кнопок | `data-req="..."` — обычный HTML-атрибут на `<a>` в любой серверной секции (nav, hero, instrumenty, cobi, zakon и т.д.), без изменений. `Zayavka.tsx` вешает один делегирующий `document`-level click-listener через `useEffect`, как в оригинале — компонентам-источникам кнопок ничего передавать не нужно |
| Валидация формы + honeypot + экран «готово» | `onSubmit` в `Zayavka.tsx`, без реального fetch — как в прототипе |
| Scroll-spy активного пункта меню (IntersectionObserver) | эффект в `Nav.tsx` |
| Кнопка «наверх» (появление после скролла) | эффект в `BackToTop.tsx` |
| Заглушка языка EN/VI («скоро») | локальный `useState` с таймером, как в прототипе |
| Reveal-анимации при скролле/по якорю | компонент-обёртка `Reveal.tsx`, применяется вокруг блоков с текущим классом `.rv` |

Вся логика переписывается на React-идиомы (хуки), но поведение и тайминги —
как в оригинальном скрипте.

## Ассеты

- `bigmark` — сейчас base64 `data:image/webp` внутри `<img>`. Декодируется
  и сохраняется как файл в `public/`, подключается через `next/image`
  с теми же `width`/`height`/`alt`.
- SVG-шум на фоне (`data:image/svg+xml` в `background-image`) — остаётся
  как есть в CSS: он декоративный, маленький, менять как файл смысла нет.

## Контент

Весь русский текст переносится дословно из прототипа в JSX — без перевода,
сокращений или перефразирования. EN/VI — только заглушки кнопок, контента
для них не создаём.

## Тестирование / проверка

Автотестов не заводим (лендинг без бизнес-логики на бэкенде). Проверка вручную
через дев-сервер (`npm run dev`) с обходом контрольного списка:

- Каждая секция присутствует и визуально совпадает с прототипом
  (шрифты, отступы, тени, цвета).
- Бургер-меню открывается/закрывается на мобильной ширине.
- Табы форматов переключаются кликом и стрелками, ARIA-атрибуты верны.
- Форма: пустая отправка показывает ошибку и фокус; заполненная — показывает
  экран «готово»; honeypot-поле не мешает обычной отправке.
- Scroll-spy подсвечивает пункт меню при прокрутке к секции.
- Кнопка «наверх» появляется после скролла и скроллит к началу.
- Reveal-анимации отрабатывают при скролле и не ломают контент при
  `prefers-reduced-motion: reduce`.
